# James's evidence bundle → Xay's dashboard

Xay owns dashboard rendering, adapters and UI tests. James owns the research
exporter, evidence selection and explanations. Existing experiment outputs remain
read-only. The dashboard starts no provider calls or experiments.

## Published input format

The integration point is **`tables/evidence_bundle.json`**, generated by James's
`python -m skeptic.analysis.evidence_bundle export` once that exporter is present
in the checkout. The dashboard does not run the exporter automatically.

The supplied format contains:

- `explanations.research_question`, `observed_result`, `limitation` — editorial
  explanations shown beside measured results.
- `example.sources[]` — Exa query, title, URL, date and extracted method.
- `example.lessons[]` — Analyst text and `built_from_verdicts_on[]`.
- `example.proposal` — SHA, slot, rationale, memory references and file path.
- `example.validation` — validation metrics, gates, verdict and failure reason.
- `memory_arm_counts[]` — source cards, lessons and proposal-reference counts.
- `sponsor_evidence` — provider status and evidence text for Exa, Modal and past.dev.

The dashboard uses the explanations and featured proposal selector, then resolves
that proposal against the local decision, memory and source files. Displayed
metrics, references and memory-use counts are checked from those source records;
free-form bundle values do not override measured results. Provider status text is
attributed to the bundle, not presented as a new API verification by the dashboard.

The featured run can be supplied as `example.run_id`, `example.run`,
`example.run_dir`, or derived from `example.proposal.file`, `.path`, or `.file_path`.
Only recognized validation run IDs and 12-character lowercase proposal SHAs are
accepted. Supplied filesystem paths are never opened directly.

The separate **`tables/pastdev_check.json`** is included in the local artifact
inventory. A later read-only recall check is distinct from remote retrieval during
the historical experiment. Raw recall payloads are not exposed by the dashboard.

## Sources used by the UI

For each named run, the adapter joins:

- `decisions.jsonl`: validation outcomes, slots and declared `MEMORY_USED` IDs.
- `memory.jsonl`: Scout source cards, Proposer rationale and Analyst lessons.
- `proposals/llm.json`: model, attempts and rejected-slot details.
- `proposals/<sha>.py`: source displayed as text after a SHA-256 prefix check.
- `budget.json`: charged call/search attempts, reported tokens and limits.

Direct source links use a declared memory ID or an exact SOURCE URL. Indirect
links traverse earlier proposal cards' explicit memory references, with their
full ID paths displayed. An Analyst lesson's earlier verdicts are joined by its
explicitly cited proposal SHAs. Chronological proximity does not create a link.

## Missing or conflicting evidence

A missing or malformed bundle does not disable the dashboard: it displays the
recorded-study explanation and reconstructs traces from local source records.
A supplied selector that cannot be resolved does not manufacture a proposal.
Run health reports missing artifacts and summary/count disagreements.

The dashboard never modifies the registered experiment, reads sealed test arrays,
executes generated code, or treats file presence as a valid published freeze.
James should verify the research interpretation; Xay's tests verify the joins,
counts, UI behavior and data boundaries.
